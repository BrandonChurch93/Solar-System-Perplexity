## Decisions

1. Scratch mode (`--scratch`, round above 900) swaps two paths and switches git off: the ledger is a copy of `kit/PROGRESS.md` at `out/work/rounds/scratch/PROGRESS.md`, the scorecards go to `out/work/rounds/scratch/scorecards/`. Every other line of code is the same as in a real round, so the scratch run tests the real code. A round above 900 without `--scratch` is refused, and `--scratch` with a round up to 900 is refused.
2. Tiers below final are allowed in scratch mode only (`--tier draft`); the tool then adds `--tier draft --motion-tier draft` to every pack command and `--tier draft` to stress and measure.
3. Whole film part names for `npm run pack -- --phase 5|6 --round N --only ...` (no `--stop`): `stills:A-B` (every final tier frame of the whole film pack with A <= frame <= B: judged frames, whole film sheet frames, hook frames, all kept in `out/work/stills/`), `film-K` (whole film sheet K), `holds` (the grid of judged hold frames), `hook` (the phone size hook images), a segment id (its motion sheet), `ID-cover`. With `--stop` the old stop names keep their meaning.
4. The record round's pack (Phase 6) publishes one folder per stop and critic (`R1-mars`, `R3-mars-part1`, `R4-mars`), the whole film folders without a stop (`R3-part1`, `R4-part1`, `R5`, `R6`, `R7-part1`, `R2-part1`, `R8-part1`). Each R2 image is judged once; a stop's R2 is tallied from the votes on its own two frames and two controls, the whole film R2 from all of them.
5. Jobs are packed by expected minutes from a cost model (samples per frame times `--sample-seconds`, default 4.3) to at most `--job-minutes` (default 15) and spread over `--workers` (default 8); a worker gets several jobs in a row.
6. The record round collects its controls itself by default; `--controls-from N` reuses those of round N.
7. In whole film and record rounds a failed R2 is counted as one major issue in the round line, as the kit says. The stop round's line is left as it was.
8. A stop round with three or more R3 parts (the Sun: frames 0, 60, terrain, rise, hold): the extra parts are added after the four old critics, so R1, R3 part 1, R3 part 2 and R4 keep the families they had; `close` reads every part.
9. `close --vote NAME=LETTER` in a whole film or record round is kept in the round's state (`votes`) and is applied again by every later `close`; a round that reuses the controls of another round takes that round's corrections with them. The stop round is as before (the correction holds for that one call).
10. In the record round the families turn by stop: the critic at seat i of stop number s (Sun is 1) gets `SLOTS[(i + round + s) % 4]`, as if the stops had been judged in rounds that follow each other. The whole film critics get `SLOTS[(i + round) % 4]`, as in a whole film round.
11. A merge commit of mine is written with `git merge --no-ff -m` and carries the trailer. Two early ones (8ca6364, 7bbddc7) do not; they were pushed and stay.

## How to run (one line each)

- Render named parts of the whole film pack on a worker: `npm run pack -- --phase 5 --round N --only stills:0-1500,film-1,hook` (parts: `stills:A-B`, `film-K`, `holds`, `hook`, a segment id; in Phase 6 also `ID-cover`). The last line says whether a render session was opened.
- The list of frames and sheets a whole film pack needs, with nothing rendered: `npm run -s pack -- --phase 5 --round N --plan`.
- Whole film round: `python3 tools/round.py start --round N --whole`, then `jobs`, `place`, `pack`, `votes`, `close`, each with `--round N`. After `start` the tool knows the round's kind from its state.
- Record round: `python3 tools/round.py start --round N --record`, then the same five steps. `pack --controls-from M` reuses the controls of round M.
- Scratch: add `--scratch` to every step and use a round above 900; `start` also takes `--tier draft --every 10 --allow-red`. Made up answers: `python3 tools/scratch_answers.py --round N | python3 tools/round.py votes --round N --scratch`.
- `jobs` takes `--workers 8 --job-minutes 15 --sample-seconds 4.3 --measure-minutes 20`.

### Decisions

1. `master.py` keeps a plan in `out/work/master/<name>/` (`plan.json`, `jobs.json`, `state.json`); the name is `<format id>-<tier>` unless `--name` is given; `out/work/master/current` names the last plan.
2. Cost model: samples per frame of the tier (the fast kinds use `fastSamplesPerFrame`) times seconds per sample (4.3 in master, times 0.45 in preview, times 3.5 in uhd, from the Mars budget table; `--sample-seconds` sets it) plus `--overhead-minutes` per job. A segment is cut into equal spans no longer than the job minutes; spans are grouped into jobs in film order; jobs go to the least loaded worker, longest first.
3. A tier fits when the busiest worker's hours are within the limit (`sandbox.sandboxMasterMaxHours`, or `previewFilmMaxHours` with `--preview`); the machine hours of all workers are printed too. `--fit` tries final, then review; for the master the floor is review, for `--preview` it is draft, because kit/05 says never below draft.
4. `place` matches attachments by file name (`SEG.spanA-B.mp4` with `.mp4.json`), checks the record (engine hash, the hashes of the stops the segment shows, tier, format, full assets, beauty, first and last frame) and the file with ffprobe (frames, size, fps, codec), and copies good pairs into the chunk folder. Attachments are never deleted. Records of another build are listed and not used.
5. `join` refuses when the tree's hashes differ from the plan, because `film.ts` deletes chunks of another build. It only runs the existing commands: `npm run film -- --segment IDS` for segments whose spans are all here (no frame is rendered, the tool says so), `npm run film -- --join`, `npm run clip -- --stop S`.
6. `cues.ts` reads the intro times from the intro records (`out/posts/intro-<stop>.mp4.json`, else `out/work/posts/`). With no record the posts table says so and `--check` prints a note, not a failure. `--check` compares `cut/CUES.md` with what would be written now, the rows of `cut/SHOTS.md` with `segments`, and `cut/SHOTS.md` with a fresh run of `tools/shots.ts` in a temporary folder.
7. I do not commit a `cut/CUES.md`: it is the Builder's Phase 6 step 9 output and the intro records are not on main yet.
8. `gauntlet.py` writes no file. By default it runs only quick checks (searches, ffprobe, frame comparisons, `npm run cues -- --check`). The slow ones are asked for with `--run gate,clone,subfolder`; they write only under `out/work/` and `dist/` and in a temporary folder. Without `--run gate` it reads the last `out/work/gate/phase-6.json` and says NOT RUN when that is older than the last commit.
9. Rules the gauntlet tool sets itself and prints with the result: no fade in means frame 0 has at least 90 percent of the mean luma of frames 1 to 30; black means no value above 2 of 255 in a film file and 4 in a kept JPEG; a post that was encoded once needs at least 40 dB at the cut and must be closer to frame 0 of the clip than to frame 1 or to the intro (`--cut-db`).
10. The tool holds a list of family names to search the interface and the README for; it also takes the names in `scorecards/*/agents.json`. The list is in a tool, not in the interface.

## MAIL 161 (2026-11-22 13:28 UTC): start builds first, the checks follow

### Decisions

1. `start` has two steps. The build step: a dirty tree is committed without a push ("Round N: polish, the tree at the build"), `origin/main` is fetched and merged, `npm run -s build` runs (the same command as G1), the hashes come from `ensureBuild()` of `tools/lib/common.ts` (called, not changed) through one `npx tsx -e` line, the state gets `commit`, `engineHash`, `stopHashes`, they are printed, and the commit is pushed. The checks step: the build once more, the hashes of the tree against the state, the tests, the gate with the full machine list (so `gate.txt` has all eleven lines as before), `gateGreen` into the state.
2. Which step runs: `--build-only` runs the build step and returns; `--checks` runs the checks step and refuses when the state has no build; a plain call runs the build step when the state has no build and then the checks step, so a plain second call after `--build-only` only checks.
3. "Moved" is decided by the hashes of the tree, not by the commit: the state's engine hash and stop hashes against what the tree gives now. Commits that touch logs, scorecards, kit files or tools give the same hashes and do not trip it. When it trips, the tool stops in one line and names the hashes; `--build-only` takes the new tree, and when the hashes changed it drops `gateGreen` and `gate.txt`.
4. `pack` (polish and record) refuses while the state has no `gateGreen`, and refuses when the tree's hashes are not the state's. A red gate with `--allow-red` writes `gateGreen` false and the pack runs, as before.
5. The state's commit on origin: after the build step and after the checks step the tool fetches, and when the state's commit is not an ancestor of `origin/main` it merges and pushes (no force); if it still is not there it prints "commit X of the state is not on origin/main: push it before the jobs go out", and the last line of `--build-only` then reads "no jobs before the push".
6. `start` without `--polish` or `--record` takes the mode from the state when the round has one.
